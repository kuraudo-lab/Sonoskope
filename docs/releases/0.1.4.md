Sonoskope 0.1.4 fixes missing microphone curves on built-in Mac input devices.

## Fixes

- A queued AVAudioEngine configuration notification could arrive immediately after input binding. Sonoskope previously stopped capture even though the engine was running with the same device and format, leaving the chart empty. It now validates the actual engine, device, format and device availability before deciding to stop. Real configuration changes still end the session safely.
- Missing microphone permission is now prominent in the main status, with a retry action and instructions for System Settings.
- Local development builds can use an ignored `.local/signing-identity` file to preserve a certificate-backed identity across rebuilds. Release automation still produces ad-hoc signed developer previews.
- Added an explicit, bounded `--microphone-check` diagnostic command. It runs the existing ten-second microphone test and reports metric counts; passive smoke checks and CI never invoke it or open a microphone.

## Validation

69 automated tests pass, including regressions for unchanged startup notifications, stopped engines, device/format changes, disconnected devices and missing-permission status. On a physical MacBook Air built-in microphone, the same ten-second check produced zero chart values before the fix and 35 after it; capture then stopped at the time limit. No raw audio was saved.

The user also confirmed the full automatic flow using Voice Memos with the built-in microphone: input curves and app labels appeared during recording, and Sonoskope returned to standby after recording stopped. Other hardware, Teams behavior and long-call impact still require broader acceptance testing.
