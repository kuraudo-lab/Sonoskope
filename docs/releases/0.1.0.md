The first Sonoskope developer preview: investigate meeting audio problems using system-level audio, Bluetooth, and network evidence on macOS.

## Downloads

- Apple Silicon (M-series): `Sonoskope-0.1.0-macos-arm64.zip`
- Intel: `Sonoskope-0.1.0-macos-x86_64.zip`
- `SHA256SUMS`: SHA-256 checksums for both archives.

Requires macOS 14.2 or later. Extract the ZIP, place `Sonoskope.app` in a stable location such as Applications, and open it. Audio status and settings are available from the menu bar.

**Signing: this developer preview is ad-hoc signed and is not notarized by Apple. Gatekeeper may prevent direct opening. It is not a Developer ID distribution. You can also review the source and build locally with `bash scripts/build-app.sh`.** Private repository downloads require an authorized GitHub account.

## Features

- Native menu-bar app, status window, settings, and silent incident notifications.
- Audio device/process activity and connection changes, with optional Bluetooth RSSI.
- App output analysis after authorization, plus explicit 10-second microphone tests.
- Last-60-second sound-level and TCP probe charts. Missing readings break lines; failures are marked separately.
- Observations distinguished from suspected causes, with evidence, recovery records, suggested next steps, and JSON export.
- Seven demo scenarios isolated from live capture.
- No microphone capture by default. Raw audio is never saved or uploaded.

## Validation and limits

Regression tests cover audio features, incident merging, recovery, unknown states, and chart history. Real device/process/network startup checks passed on the development Mac. The user confirmed that audio levels changed with playback after granting system audio recording permission.

Levels are not quality scores. TCP probes are not actual meeting latency or packet-loss measurements. Local audio cannot verify remote listening or the headset's acoustic output. Physical Bluetooth faults, two-endpoint calls, microphone hardware tests, notification delivery, and long-term false-positive rates still require acceptance testing. See `docs/validation.md` for the full scope.

The v0.1.0 app has a Chinese interface. English/Chinese localization is available starting with v0.1.2.
