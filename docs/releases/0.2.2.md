# Sonoskope 0.2.2

Automatically pause monitoring after sustained output silence, with a configurable timeout that defaults to five minutes.

- **Automatic pause:** continuous near-zero output for the configured duration pauses output capture, microphone capture, hardware polling and network probes. The status explains why monitoring stopped; choose **Resume monitoring** to restart.
- **Configurable timeout:** Settings → Capture scope → Automatically pause after output silence defaults to **5 minutes**. Choose 1–60 minutes or disable it. The preference survives relaunch; monitoring opt-ins are retained, and the automatic pause applies to the current run.
- **Measured silence only:** both output RMS and peak must be at or below −100 dBFS. 0 dBFS is full scale, not silence. Missing, stale or discontinuous data does not count as silence. Sound, capture/scope changes, sleep and demo entry reset the timer. Demo readings cannot trigger a live pause.
- **Signed distribution:** Developer ID signed and Apple-notarized applications, DMGs and PKGs for Apple Silicon and Intel, plus signed update ZIPs using the existing release identity.

## Installation

Requires macOS 14.2 or later. From 0.2.0 or later, use **Check for Updates**, then **Install and Relaunch**. For manual installation, quit Sonoskope, choose `arm64` for Apple Silicon or `x86_64` for Intel, and install into Applications. DMG, PKG and ZIP packages are available; `SHA256SUMS` covers all six files.

## Validation and remaining checks

88 automated tests passed, including the five-minute boundary, full monitoring pause, manual resume with a fresh timer, sound resetting the timer, missing/stale/discontinuous data, sleep, scope changes, demo isolation, saved preferences and disabling the timeout. Application build and whitespace checks passed.

This remains a preview. Actual silent-output triggering on physical devices, an hours-long monitoring soak, clean-user installation and permission-dialog behavior require separate runtime acceptance. This feature reduces unnecessary monitoring; it does not establish that every performance issue is resolved. Local PCM metrics do not measure actual headset acoustic output or remote audio quality. No raw audio is saved.
