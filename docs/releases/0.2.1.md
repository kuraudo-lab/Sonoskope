# Sonoskope 0.2.1

Monitoring responsiveness improvements, restored output-analysis preferences, and improved window activation around permission dialogs.

- **Monitoring responsiveness:** hardware polling now runs serially off the UI thread. Audio delivery retains at most one pending metric window per capture rather than accumulating UI tasks. Skipped windows are marked as missing collector data, never as proof of an acoustic defect.
- **Relaunch preferences:** the global output-analysis opt-in survives restarting the app. A process-specific selection is not restored as global capture. macOS still controls permission grants; this preference does not bypass authorization or prove permission is valid.
- **Window activation:** visible windows use normal application activation to address settings losing focus around privacy prompts. A Dock icon appears while windows are open; closing all windows returns to menu-bar-only operation.
- **Demo isolation:** startup demo selection is resolved before any restored live capture starts.
- **Signed distribution:** Developer ID signed and Apple-notarized apps, DMGs and PKGs for Apple Silicon and Intel, with signed update ZIPs. Release builds retain the same signing identity as 0.2.0.

## Installation

Requires macOS 14.2 or later. From 0.2.0, use **Check for Updates**, then **Install and Relaunch** when ready. For manual installation, quit Sonoskope, choose `arm64` for Apple Silicon or `x86_64` for Intel, and install into Applications. DMG, PKG and ZIP downloads are available; `SHA256SUMS` covers all six packages.

## Validation and remaining checks

82 automated tests passed, including relaunch preference preservation, off-main hardware queries, and 10,000 metric windows arriving while UI delivery is stalled. The relaunch test fails with the original preference behavior. Build and passive startup checks passed without enabling microphone or output capture.

This remains a preview. An hours-long monitoring soak, actual permission persistence across relaunch, privacy-dialog focus behavior, clean-user installation and physical-device acceptance still require separate verification. These fixes address identified code paths; they do not establish that every reported freeze or system permission prompt is resolved. Local metrics do not establish remote call quality or actual headset acoustic output. No raw audio is saved.
